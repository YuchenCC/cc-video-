# Character Catalog

本目录记录视频人物 IP 的姿态、情绪、画面语义和推荐使用场景。

人物图片均为透明背景 PNG。角色用于建立情绪、代替观众提出问题或引导注意力，不应成为技术图解的永久主体。

## 图片分析

### `7.png` — 挥手问候

![挥手问候](7.png)

- 姿态：半身正面，右手高举挥手，身体轻微倾斜。
- 情绪：热情、欢迎、积极。
- 视觉方向：动作集中在画面右上方。
- 推荐场景：
  - 视频开场和栏目欢迎。
  - 新章节开始时短暂露出。
  - 向观众发出邀请，例如“我们一起看一下”。
- 推荐位置：画面左下或中左，让挥手方向朝向标题或主体。
- 避免：错误说明、严肃警告或失败结论。

### `8.png` — 惊讶发现

![惊讶发现](8.png)

- 姿态：双手托脸，张嘴，正面注视。
- 情绪：惊讶、意外、突然发现问题。
- 视觉方向：正面聚焦，适合作为问题反应。
- 推荐场景：
  - 展示反常结果或意外报错。
  - 抛出“为什么会这样”的问题。
  - 对比前突出旧方案的缺陷。
- 推荐位置：画面左侧或右侧，与错误提示、异常结果并列。
- 避免：普通信息说明；高频使用会削弱惊讶效果。

### `9.png` — 困倦等待

![困倦等待](9.png)

- 姿态：坐姿，揉眼打哈欠，旁有 `Zzz`。
- 情绪：疲惫、等待、无聊、流程耗时。
- 视觉方向：重心在下方，适合压在画面底部。
- 推荐场景：
  - 编译、安装、部署或任务执行时间过长。
  - 手工流程重复且低效。
  - 表达阻塞、等待和性能问题。
- 推荐位置：画面左下或右下，旁边保留耗时数字或进度条。
- 避免：仅表达“休息”；技术视频中应明确对应等待成本。

### `17.png` — 振臂成功

![振臂成功](17.png)

- 姿态：双拳上举，其中一只拳头伸向右上。
- 情绪：成功、振奋、目标达成。
- 视觉方向：强烈指向右上方。
- 推荐场景：
  - 修复完成、部署成功、性能提升。
  - 一组步骤完成后的阶段性收束。
  - 展示方案带来的积极结果。
- 推荐位置：画面左侧，使上举动作朝向右侧结果卡片。
- 避免：普通步骤完成后反复出现；仅用于明确成果。

### `18.png` — 托腮思考

![托腮思考](18.png)

- 姿态：一手托腮，另一手抱胸，眉头微皱，旁有问号。
- 情绪：疑问、分析、推理、谨慎判断。
- 视觉方向：正面偏静态，适合承接问题。
- 推荐场景：
  - 引出技术原理或“为什么”。
  - 在两个方案之间做选择。
  - 暂停流程，要求观众关注一个关键条件。
- 推荐位置：画面左侧，右侧放问题、选项或待解释结构。
- 避免：已经给出明确结论后继续使用。

### `19.png` — 生气警告

![生气警告](19.png)

- 姿态：全身站立、双臂交叉、眉头紧锁，带怒气符号。
- 情绪：不满、冲突、警告、明显错误。
- 视觉方向：正面且封闭，阻断感较强。
- 推荐场景：
  - 严重反模式和明确禁止项。
  - 权限冲突、版本冲突或错误配置。
  - 强调“不要这样做”。
- 推荐位置：问题区域一侧，搭配珊瑚色错误卡片或禁止符号。
- 避免：轻微提示；不要用愤怒角色代替准确的错误说明。

### `27.png` — 点赞认可

![点赞认可](27.png)

- 姿态：一只手的大拇指伸向镜头，眨眼微笑。
- 情绪：认可、推荐、正确、可靠。
- 视觉方向：拇指占据左侧前景，视觉冲击强。
- 推荐场景：
  - 最佳实践、推荐配置和正确答案。
  - 测试通过、检查完成。
  - 总结方案优势。
- 推荐位置：画面右侧或右下，避免放大后遮挡左侧主体。
- 避免：中立说明；它代表明确正向判断。

### `28.png` — 友好感谢

![友好感谢](28.png)

- 姿态：半身前倾，双手在身前合拢，旁有爱心。
- 情绪：友好、感谢、喜爱、温和。
- 视觉方向：重心向下且略向画面左侧倾斜。
- 推荐场景：
  - 视频结尾感谢观看。
  - 表达社区协作、用户喜爱或友好体验。
  - 轻量的关注、订阅或下一期提示。
- 推荐位置：画面右下或居中偏下。
- 避免：严肃技术结论或故障分析。

### `29.png` — 奔跑行动

![奔跑行动](29.png)

- 姿态：向画面左侧奔跑，身体前倾，带速度线和烟尘。
- 情绪：行动、启动、快速推进、加速。
- 视觉方向：明确朝左运动。
- 推荐场景：
  - 启动程序、执行命令、进入下一阶段。
  - 表达性能加速或迁移过程。
  - 章节间从右向左的动态引导。
- 推荐位置：画面右侧，为左侧运动方向预留空间。
- 避免：
  - 不要水平翻转图片，避免文字和角色细节产生不一致。
  - 不用于静态定义或需要沉稳阅读的架构图。

### `37.png` — 开怀大笑

![开怀大笑](37.png)

- 姿态：半身正面，闭眼大笑，双臂交叉。
- 情绪：轻松、有趣、释然、原来如此。
- 视觉方向：正面聚焦。
- 推荐场景：
  - 一个复杂问题被简单化后的轻松收束。
  - 技术误区或程序员共鸣梗。
  - 较轻松的章节过渡。
- 推荐位置：画面边侧或底部，不与主要技术图解并列抢焦点。
- 避免：严重错误、生产事故或安全风险场景。

### `38.png` — 崩溃大哭

![崩溃大哭](38.png)

- 姿态：坐地哭泣，双拳紧握，泪水大量喷出。
- 情绪：强烈挫败、崩溃、严重失败。
- 视觉方向：重心在画面下部，情绪强度高。
- 推荐场景：
  - 构建全面失败、数据丢失或生产事故的夸张表达。
  - 展示旧流程造成的巨大维护成本。
  - 用于技术痛点的情绪化开场。
- 推荐位置：画面左下或右下，旁边放明确故障原因。
- 避免：
  - 普通报错和轻微问题。
  - 与 `19.png` 同时出现，避免情绪过载。

### `39.png` — 举手讲解

![举手讲解](39.png)

- 姿态：站立半身，一手叉腰，一手举起食指，旁有对话气泡。
- 情绪：自信、清晰、提示、讲解。
- 视觉方向：举起的手位于画面右侧，可自然指向上方信息。
- 推荐场景：
  - 引出定义、结论和关键提示。
  - 作为视频中的讲解者 IP。
  - 章节标题、知识点总结和注意事项。
- 推荐位置：画面左下或中左，右上方放标题、标签或重点卡片。
- 避免：纯装饰常驻；出现时必须承担提示或讲解功能。

## 情绪强度

选择人物时优先使用最低但足够表达语义的情绪强度。

| 强度 | 图片 | 适用范围 |
|---|---|---|
| 轻 | `7.png`、`28.png`、`39.png` | 问候、提示、友好引导 |
| 中 | `17.png`、`18.png`、`27.png`、`29.png`、`37.png` | 推理、行动、认可、成功 |
| 强 | `8.png`、`9.png`、`19.png`、`38.png` | 异常、疲惫、警告、崩溃 |

强情绪图片应短暂出现，通常不超过一个语义段落。

## 构图和动画规范

- 默认每个分镜最多出现一个人物形象。
- 人物面积建议不超过画面面积的 20%；开场、结尾或纯情绪反应镜头可放宽到 30%。
- 人物不得遮挡流程箭头、核心节点、代码和字幕安全区。
- 优先放在画面边侧，让视线和手势朝向技术主体。
- 入场使用 `fadeIn`、`slideUp` 或轻量 `popIn`。
- 退场使用淡出或局部替换，不做旋转、弹跳和大幅位移。
- 不对 PNG 添加厚重阴影、发光或渐变背景。
- 保留透明通道和原始宽高比，不拉伸、不裁掉手势与情绪符号。
- 同一幕中不要同时使用两个高情绪人物。

## 引用约定

分镜文档中使用相对工程根目录的路径：

```markdown
人物：assets/characters/39.png
用途：讲解者举手，引出右上方的核心定义
位置：左下
入场：0.4s fadeIn
退场：结论出现后 localReplace
```

代码中的资源加载方式由最终渲染框架决定，但素材源路径必须保持为：

```text
assets/characters/<文件名>.png
```

不复制同一图片到场景目录，不通过文件名猜测语义；选图前查阅本目录。
