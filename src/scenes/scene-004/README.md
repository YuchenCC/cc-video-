# Scene 004 — 日志篇

- 时长：53.5 秒。
- 章节 Beat：0–2.5 秒使用 `TitleTransition`，文本为“日志篇”。
- 核心概念：日志脱敏要按日志形态选择处理路径；有字段名复用接口规则，无字段名启用有限兜底，并控制性能边界。
- 字幕：保留底部字幕与 `scripts/subtitles.md` 中的 scene-004 时间。
- 构图：浅灰白板 + concept 三列区域；Terminal 作为连续主物件，左侧承载来源/边界卡片，右侧承载屏幕文字和人物反馈。
- 正文 Beat：2.5 秒后开始，按用户分镜顺序轻微压缩进剩余时长。
  - 大 Terminal 滚动到漏脱敏手机号，`keyboard.png` 在下方，右侧 `8.png` 表示发现异常。
  - 上游、当前、下游三类来源分别使用 `shangyou.png`、`sys.png`、`xiayou.png`，依次通过缓慢生长的虚线直线箭头汇入统一日志窗口；箭头尖使用独立等比三角形，右侧显示“日志来源 ≠ 只有本系统”。
  - 6 张字段卡翻页，第二页和第五页以红色虚线表示人工漏掉字段。
  - 主时间轴 02:00（Scene 内 21.2s）中央出现脱敏规则卡，左上 `terminal: response` 与左下 `terminal: log4j` 展示未脱敏内容。
  - 两个 Terminal 同时缩小汇入规则卡，在最小尺度切换为脱敏结果，再从右侧放大抛出并停在与初始位置镜像对称的位置。

  - `engine.png` 从右侧用 2 秒缓慢移向中央；到位后 Terminal 轻微缓动，原文替换为脱敏结果，并用红色手绘圈标记手机号和邮箱。
  - 主时间轴 02:18 左侧依次出现 `mobile.png`、`card.png`、`email.png`，对应手机号、证件号和邮箱三类明确特征。

- 验收：字幕不被遮挡；主要内容不进入底部安全区；明确表达“兜底不是全量扫描，只处理边界明确的数据类型”。
