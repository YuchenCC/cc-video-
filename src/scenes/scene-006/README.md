# Scene 006 — AI 工程化

- 时长：59.5 秒。
- 章节 Beat：0–2.5 秒使用 `TitleTransition`，文本为“AI 工程化”。
- 正文时间基准：用户给出的 0–57 秒以正文音频起点计算，对应场景内部 2.5–59.5 秒。
- 核心概念：AI 生成内容必须经过需求拆解、分层验证和长期约束，才能形成可追踪、可运行、可验证的交付。
- 构图：统一使用 `concept-expansion` 浅色白板语言，从版本路线图逐步演化为任务流程、质量金字塔和交付闭环。

## Beat

1. **2.5–13.5 秒｜交付版本路线图**
   - 卡片内容与路线图参考逐项对应：MVP「接入可行性」、R2「扩展与治理能力」、R2.5「模拟系统接入组件」、R2.6「Dashboard 工作台」、R3「未来版本 / 规划方向」。
   - MVP 先在中轴出现；R2 从 MVP 右侧衍生并停稳，二者一起左移让 R2 接管中轴。
   - R2 再衍生 R2.5，三者一起左移让 R2.5 接管中轴；随后依次从右侧生成 R2.6 和 R3。
   - 底部迭代链使用“反馈 / 问题 → PRD → Issue → 实现 → 测试 → 文档记忆 → 下一轮”。
   - 结尾重新聚焦 MVP 节点，连续交接到需求拆解 Beat。
2. **13.5–30.5 秒｜需求拆解**
   - MVP 节点本体直接移动到说明书落点，落位后原位形变为“需求说明书”，副标题为“MVP版本”。
   - 说明书以树状关系横向拆出三个 Issue：接入能力、治理规则、结果展示。
   - 每个 Issue 再拆出两个 Task；右侧出现“交付验收”组件，六个 Task 依次飞入并点亮验收进度。
   - 所有拆解结构清空后，“交付验收”组件移动到画面中央完成收束。
3. **30.5–44.5 秒｜质量金字塔**
   - 三层结构为模块级测试、集成级测试、Demo 黑盒验收。
   - 右侧结果面板展示自动化测试、接口/日志/报告验证、人工边界复核。
   - 不使用虚构的测试数量或通过率。
4. **44.5–59.5 秒｜约束驱动的交付闭环**
   - 存量项目 → 低侵入接入 → 持续记忆 → 验收闭环 → 可验证交付。
   - 持续记忆明确保留兼容存量技术栈、异常不影响业务、不保存敏感原文。
   - 最终收束为可追踪、可运行、可验证。

## 动画与转场

- MVP 节点是路线图到需求说明书的连续迁移锚点。
- 路线与树状关系使用 `arrowDraw`；Issue / Task 使用错峰衍生；质量分层使用由下至上的 `scaleFocus`。
- 前三个 Beat 使用对象聚焦和 `localReplace` 连续推进；质量金字塔到交付闭环使用一次 `wipeSoft`。
- 最终节点保持完整对比度，其余流程降至 35%，形成明确收束。

## 验收

- 不听口播也能理解“计划 → 拆解 → 验证 → 交付”的关系。
- MVP 到需求说明书的移动连续，Task 汇入交付验收后画面收束明确。
- 金字塔层级、结果面板和最终三项交付状态均在字幕安全区之上。
- 参考图只提供信息结构，最终视觉必须保持项目的白板式蓝绿技术图解语言。
